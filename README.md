# Time Manager

Учебное мобильное приложение для тайм-менеджмента под Android. Его сделала команда из 7 первокурсников. Главная цель проекта: научиться вместе работать с Git и GitHub.

Стек: React Native + Expo (JavaScript). Данные хранятся на телефоне (AsyncStorage), интернет не нужен.

## Что умеет приложение

Внизу экрана 4 вкладки:

- **Задачи.** Все задачи списком, фильтр, отметка «выполнено», удаление.
- **Расписание.** План на день, неделю или месяц. Можно добавить сразу несколько задач на день.
- **Статистика.** Сколько задач выполнено, продуктивность по приоритетам, графики.
- **Заметки.** Папки и заметки внутри них: итоги дня, мысли, дневник.

Все разделы работают с одними и теми же задачами через общий модуль `src/storage.js`. Задача, добавленная в Расписании, сразу видна в Задачах и учитывается в Статистике.

## Как установить

**Android:** скачайте APK из раздела [Releases](https://github.com/litsemerx-dot/time-manager/releases) на телефон и откройте файл. Телефон может попросить разрешить установку из неизвестного источника.

**Из исходного кода (Android или iPhone через Expo Go):**

    git clone https://github.com/litsemerx-dot/time-manager.git
    cd time-manager
    npm install
    npx expo start

Отсканируйте QR-код приложением Expo Go.

## Как мы работали с Git

Каждая часть делалась одним и тем же циклом:

1. `git pull` свежего `main`, затем своя ветка: `andrey/tabs`, `Kirill/priority-widget`, `vlad/schedule`, `Liza/tasks-list`.
2. Коммиты и `git push` своей ветки на GitHub.
3. Pull request в `main`. `main` защищён: без одобрения другого участника влить нельзя.
4. Ревью. Например, в PR со Статистикой ревьюер нашёл лишние изменения в `package.json`, а в PR с Задачами попросил подключить общее хранилище вместо тестового. Авторы исправили это в той же ветке, и PR обновился сам.
5. Merge в `main`.

Все PR можно посмотреть во вкладке [Pull requests](https://github.com/litsemerx-dot/time-manager/pulls?q=is%3Apr).

## Правила

1. В `main` напрямую не пушим. Только через pull request (PR).
2. Ветка называется `имя/что-делаю`, например `andrey/storage`.
3. Коммит: короткая фраза о том, что сделано, например «Добавил кнопку удаления задачи».
4. Один PR = одна фича или одно исправление.
5. Каждый PR проверяет сосед по кругу: 1 → 2 → 3 → 4 → 5 → 6 → 7 → 1.
6. Новые библиотеки (`npx expo install ...`) ставим только договорившись с тимлидом.
7. Код, который не можешь объяснить, в PR не отправляем.

## Как работать каждый день (для команды)

    git checkout main
    git pull
    npm install
    git checkout -b имя/что-делаю
    # ...работаешь, проверяешь на телефоне через npx expo start...
    git add .
    git commit -m "Что сделал"
    git push -u origin имя/что-делаю

Потом на GitHub жмёшь **Compare & pull request**, назначаешь ревьюера и ждёшь одобрения.
